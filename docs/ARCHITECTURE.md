# Application architecture

`mashi/imaging.py` validates and orients raster bytes, composites transparency on white and proposes connected ink. `ocr.py` wraps a local optional Tesseract process. `store.py` stores project documents in SQLite with atomic project revision checks. `app.py` exposes the loopback API. `tracing.py` isolates dark pixels, traces alpha-masked ink, flattens tracer translations and validates geometry. `exporting.py` converts those same paths to UFO glyphs and invokes fontmake for TTF. `predictors.py` defines the completion boundary and an honest unavailable state.

## Coordinates and lineage

Schema 2 has explicit pages, shared typography and exact sequence choices. `projects.py` owns page views and the common sample resolver; `backups.py` owns read-only editable backup, staged import and durable first-write legacy recovery. Page identity is carried into each selected glyph's source metadata. See [PROJECTS_BACKUPS.md](PROJECTS_BACKUPS.md) for schema, concurrency, archive validation and limits.

- Keep original bytes and their SHA-256. Decode and EXIF-orient once. Store a separate SHA-256 for the RGB canonical PNG, the original dimensions and orientation, and the ordered transformation log.
- Every region uses **current working image pixels**, top-left origin, half-open `[x0,y0,x1,y1)` bounds. Display resizing affects only the canvas. Page preparation records pixel-edge forward/inverse homographies; each new/edited crop stores its polygon in preserved oriented-source and original-file coordinates. EXIF orientation has a numeric inverse mapping. Pixel-center adjustment is explicit at the OpenCV sampling boundary.
- The original upload and initial oriented PNG stay immutable. Prepared pages use generated immutable asset names, their own hashes and a transformation/options record. Applying preparation archives the previous image/regions and creates fresh unconfirmed proposals. Restore switches back to identical prior image bytes and crop state. Lighting/threshold changes are regenerated from source pixels; these photometric operations are not mathematically invertible.
- Each region has a random ID, independent revision, active flag, exact label, confirmation, source, provenance, optional OCR word suggestion and optional vector. SQLite retains inactive split/merge parents, discarded regions and before-edit snapshots. Stale region revisions are rejected.
- Splitting creates two unconfirmed, unlabelled children. Merging creates an unconfirmed, unlabelled bounding-box union. A bounding-box union can include neighboring ink; the user must inspect and correct it. Neither operation reuses a possibly misleading vector or inferred label.
- Crop edits invalidate traced vectors. Label changes are explicitly saved with confirmation. Re-tracing replaces the active vector; earlier edit snapshots remain in history. Concurrent project updates use optimistic revision checks.
- New-crop and OCR requests require the displayed project revision, so another tab's preparation cannot accept coordinates intended for old pixels. Image loads bind to an expected canonical hash. Raster and metadata are committed together in the client; late loads are ignored. Reloading recovers current saved state.
- Geometry is local crop coordinates. Export applies `x_font = x_crop * scale + 50`, `y_font = (baseline - y_crop) * scale`. The explicit Y flip maps image-down to font-up. The baseline remains adjustable in crop pixels; scale is font units per pixel; advance is font units. UPM is 1,000.
- Trace provenance includes threshold, VTracer version and edited status. A retrace saves the entire previous region/vector/metrics as a `before-retrace` history snapshot before replacing the current outline. It can be recovered through the saved-history UI in the local project. Font glyph libs include region/revision, exact sequence, canonical image hash, crop and edit status. Font archives omit editing histories and are not project backups.
- Built-in practice pages persist project `source_kind=synthetic-fixture` and matching region provenance through all crop operations and OCR. Default font export rejects them. An explicit synthetic test export uses a separate font family/filenames and writes the source into coverage, glyph libs, SVG metadata and the export readme. Synthetic glyphs never count as observed handwriting coverage.

## Unicode and shaping

Labels accept Malayalam block codepoints plus ZWJ/ZWNJ, up to 32 codepoints. No normalization is performed. The UI exposes the exact sequence. OCR text is a separate untouched suggestion; user correction is required even if recognition appears plausible. A connected component, codepoint, grapheme cluster and font glyph are different entities.

Confirmed single-codepoint forms receive cmap entries. Whole-sequence observations may receive an `akhn` rule only when all referenced input glyphs exist. Longer sequences are ordered first. Every emitted glyph reference is locally constructed and validated. No complete FEA is borrowed from a reference font. `mlym` and `mlm2` identify shaping-system versions; they do not select traditional versus modern orthography.

The integrated typography V1 backend supplies a bounded mlm2 repertoire, HarfBuzz reordering and adjustable geometry-estimated virama anchors. It does not infer reader-approved calligraphy or complete contextual/mark-stack behavior. See TYPOGRAPHY.md and exact-text preflight; successful compilation alone is insufficient evidence of usable Malayalam shaping.

`proofing.py` caches bounded exact-text previews by revision/options/provenance; the proof UI draws positioned outlines from the actual compiled TTF. Required proof text/settings enter UI exports, and stale compilation results are rejected. See [PROOFING.md](PROOFING.md) for cancellation, diagnostics and API compatibility.

## Optional completion boundary

`ml_engine.py` validates NPZ headers/hash/schema without pickle and runs only the pinned PCA/mean arithmetic; template payloads are never loaded. `ml_capture.py` rasterizes approved vector geometry into a declared baseline-aware canvas with retained transforms; no crop stretching is used. `ml_service.py` accepts only operator-configured checkpoint paths, owns bounded cancelable worker processes and tracks explicit loading. Normal capture/OCR/trace paths do not need SciPy or any checkpoint. `completion_suggestions` is a separate document collection, never page-coordinate regions. Its own raster canvas, vector edits, review revision/history, model/reference hashes and source terms persist. Accepted suggestions remain model-generated. The exporter only includes them under a separate explicit generated-font choice with the current reference and source-notice gates. See [LOCAL_COMPLETION.md](LOCAL_COMPLETION.md).

`export_project_snapshot` projects only the current eligible source forms and, for explicit generated output, eligible accepted suggestions into `project.json`. It retains coordinate/source provenance and current vectors, omits pending/rejected/excluded candidates and all history/preparation snapshots, and declares `full_project_backup=false`. The same selection controls compiled glyphs and SVGs. Inference inventory and exclusion IDs in coverage reports are diagnostics, not exported model geometry.

## Local security and privacy

The provided CLI binds `127.0.0.1`. Host validation allows localhost/127.0.0.1, same-origin checks reject external Origins, and every mutation needs a random process token read from the same-origin session endpoint. There is no permissive CORS. CSP restricts resources to this app, disallows embedding and plugins, and the app loads no remote scripts, fonts or analytics. Capture, OCR, tracing, completion and font building run locally. The explicit **Add Malayalam data** action downloads hash-pinned public Tesseract assets from GitHub; it sends no photos or project text and is never triggered by readiness or normal capture. No remote inference provider is called. Loopback is not a defence against other programs running as the same local user.

Byte and decoded-pixel limits apply before tracing. Only JPEG/PNG/WebP rasters are accepted. Storage paths use generated UUIDs and internal filenames; supplied paths and filenames are never opened. No uploaded SVG is accepted. Vector edits accept a bounded list of SVG geometry strings, validated as closed finite contours; markup, scripts, external references and foreign objects cannot pass. XML exports are built with ElementTree. OCR and font compilation use argument lists, never shell interpolation, with timeouts.

`.mashi/`, photos, environments, caches and model checkpoints are excluded from Git. Font ZIPs contain selected current glyph geometry and metadata, including labels, coordinates and hashes. The separate editable `.mashi.zip` backup intentionally includes original photographs, all samples and referenced histories; users should review it before sharing. Model files remain external. There is no telemetry, automatic cloud fallback or API-key requirement. A future BYOK feature must ask for explicit image-upload opt-in before sending photographs anywhere.
